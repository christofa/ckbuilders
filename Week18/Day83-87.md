## Understanding How The Database Writes To Vote Cells

### The Aim for This Week
After finishing up last week's security priorities for the review, I noticed a burden: votes are verified cryptographically, but they are still stored only in Turso.
So this means if the data base is changed, lost, or crashes/corrupts, we wouldn't be able to rebuild the leadboard directly from CKB.That means voting is not fully trust-minimized yet.

So this week, the goal was not to start coding immediately. I focused on understanding how on-chain voting should work on CKB observing the data structure, transaction flow, verification process, and how the leadboard could eventually be rebuilt entirely from blockchain data.

### What Problem This creates
- The First Problem: The leadboard can't be verified directly from CKB so anyone checking it would have to trust the database.
- The Second Problem: If Turso crashes or gets corrupted or changes, there will be no on-chain record to rebuild the leadboard from. 
- The Third Problem: votes only exist in the database, so users can't independently verify the votes or reconstruct the correct leadboard from CKB if the database is compromised. 

### The desired output
User clicks Vote -> Frontend builds a Vote Cell transaction -> User signs the transaction (wallet popup) -> Transaction broadcast to CKB testnet (txHash returned) -> Frontend POSTs { entryId, txHash } to backend -> Backend fetches the real transaction from CKB -> Backend parses and verifies the Vote Cell data -> Backend writes row to Turso WITH tx_hash stored

### What I Learn
- CKB Cells don't have to just store value. They can be used to store public data verifiable to everyone – like votes-as well.

- To build a vote cell, the steps involved are similar in spirit to Contest and Entry cells: encoding, capacity, completing transaction, and broadcasting it.

- The system is trustless if the state can persist even without the application. If the ContestLedger somehow vanished and somehow disappeared for good, the results, votes, etc. Can still be retrieved from CKB.

- A small amount of CKB is allocated to this vote cell. It serves not only to allocate, but also to combat spam without application controls.
