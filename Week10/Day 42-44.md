# Day 42-44: May 26th - 29th, 2026

## Building the Browse Page - Real Data from SQLite

### What I built today
- Firstly, I created a new api route (/api/contests/list)
- Then, replaced the mock contests with real API data on the browse page
- Then added the error handling states
- Also built adaptContest () to bridge the database and UI shapes 
- Finally, ran end-to-end tests from the create contest to the browse page

### The Browse Page Flow
The User loads /browse -> the useEffect triggers on -> fetch("/api/contests/list") -> then the API reads from the SQLite contests table -> It returns an array of real contests -> page renders real data

### What I learned
- The adapter function: it's a pattern that converts one data shape into another without changing either side. 
- Learned my database uses snake_case column names (entry_type), but my ContestCard component expects camelCase (entryType)
- Learnt the importance of adding UI states for handling all states of the page.
