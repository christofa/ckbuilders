## Building the Create Contest Page (Validation & Error Handling)

### What I did 
- Added form validation before any blockchain call
- Fixed Typescript type errors in the step state
- Inserted wallet connection warning UI
- Improved error message for common failure cases 
- Reworked the wallet connection page to correct all spotted errors (bonus)

### What I Learned
- One very important lesson I learnt today is to validate everything BEFORE making any blockchain call. 
- A failed blockchain transaction still costs gas fees but a failed validation costs nothing 
- Validating before transacting importantly helps to prevent wasting fees and confusing error messages.
- Noticed blockchain UX has a unique challenge which is, operations are slow and irreversible

### Challenges Encounted/Solutions 
- I hit a TypeScript error trying to type my step state. The correct patter was to define a union type first: 

```typescript
type Step = "idle" | "signing" | "broadcasting" | "saving" | "done"
const [step, setStep] = useState("idle")
```
- I put in a yellow banner to indicate that the wallet is not connected. The warning banner will appear above
the publish button for users to see before clicking on it. The publish button is also disabled with 50% opacity when wallet is not connected or form is invalid.

- I created three error handling layers:
    - Layer 1 - Validation of the form (before transaction): 
    "Please enter information in all fields. Minimum reward = 100 CKB."

    - Layer 2 - Wallet errors (during signing):
    "Wallet connection failed" or "The request was rejected by user"
    Appears when user closes the wallet popup

    - Layer 3 - Network errors (after broadcasting):
    "Transaction could not be resolved" – usually occurs because of node 
    Display the error and allow retry
