## Building the Create Contest Page (Blockchain Logic)

### What I did
- Connected the create contest form to the CKB blockchain
- Created the contest cell structiure
- Added an create contest API route 
- Set up the contests table in SQLite

### What I Learned
- The contest has to live in two places, for two different reasons.
- The data primarily lives on-chain in a CKB cell permanently and cannot be edited or changed by anyone, not even me as the platform owner.
- Then, a lightweight index lives in my SQLite database. It stores things like the TX hash, title, creator address, and deadline so I can quickly list avaliable contests on the dashboard without scanning the entire blockchain every time. 
- The SQLite just serves as a bookmark and the CKB is the actual book. 

### How the contest Cell works
A transaction will be created when a user submits a contest as follows:

Input cells:   creator’s current CKB cells (for payment)
Output cell:   newly created Contest Cell

```json
{
  "title": "80s Dance Challenge",
  "description": "Show your best moves",
  "entryType": "video",
  "reward": 1000,
  "deadline": "2026-06-01",
  "creator": "ckt1qzda0cr08m85...",
  "status": "active",
  "platform": "ContestLedger"
}
```

This JSON is converted to hex first before storing because CKB stores raw bytes in the data field, not plain text. On reading it back we convert hex → bytes → JSON.

### The Publish/Create flow
1. Validates form fields
2. Then checks if wallet is connected
3. Get creator address from wallet
4. Package contest data in JSON
5. Convert the JSON to hex 
6. Then calculate minimum capacity 
7. Build CKB transaction 
8. Sign and send to testnet 
9. Save Tx hash to SQLite 
10. Redirect to dashboard

Note: Flow 7-8 typically happens inside the user's wallet. No private key is touched at all. The wallet sign locally and sends directly to CKB
