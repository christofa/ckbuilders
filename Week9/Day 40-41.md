## CKB Transaction Lifecycle — From Signing to On-Chain

### What I Studied
- Studied the full journey of a CKB transaction from the point a user clicks a button to the point it's confirmed on-chain. Studied this because it is fundamental knowledge I need to understand WHY the contest page works the way it does.

### Why I studied this
Every time I call the signer.senTransaction(tx) something happens that I don't really get, and so, I went deep on knowing what that something is.

### What I Learned
- The full transaction lifecycle 
    - The construction stage (happens in the browser)
    - The Completion Stage
    - The Signing Stage (in the wallet)
    - The Broadcasting stage (sent to the network)
    - Waiting for the Mail (Mempool)
    - The Approval Stage (Confirmation)
- Learnt how this Lifecycle Matters to the contestLedger project
- This is valuable knowledge for ContestLedger since it helps me build a responsive interface that displays proper status labels according to the process stage: "Waiting for wallet..." during signing and "Broadcasting to CKB..." to notify the user about sending.
- Moreover, this knowledge allowed me to make another crucial decision in the app development process – saving the contest to my local database at the broadcast stage (Stage 4) rather than the confirmation stage (Stage 6). This enables real-time changes in the dashboard for the user. And if needed, he can always find information about the contest using the TX ID from CKB Block Explorers.
- The key advantage here is being able to show users an actual pending state rather than an ambiguous loading one.
