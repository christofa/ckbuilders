# Day 59-65: July 1st - July 8th, 2026

## Hackathon Phase 1: The Problem, The Plan, and Building the Core

### Project Idea

The idea is to create a fully typed TypeScript SDK for the Fiber Network that makes interacting with its JSON-RPC API easier. I will include a built-in MockClient, allowing develpers to build and test Fiber payments without having to run a Fiber node.

The goal is to get rid of the friction JavaSript developers have to go through when developing on Fiber especially JS developers new to Fiber.

### The Problems I Identified

So while creating ContestLedger, integrating Fiber payments were really difficult beacuse:

- There was no official JavaScript/TypeScript SDK
- Developers had to manually write JSON-RPC fetch requests
- There were no TypeScript types or autocomplete
- Response structures were unclear
- Testing required running a local Fiber node, funding it with testnet CKB, and connecting peers before writing any application logic

### What I Did First Week

- Studied the complete Fiber RPC docuementation
- Decided on and prioritied the curcial methods from the RPC that are required for the SDK
- Implemented the TypeScript type system for the project.
- Implemented the LiveClient wrapper Tier 1 Fiber RPC methods.
- Implemented the MockClient including:
  - Channel life cycle management
  - Payment simulation
  - Invoice processing
  - Balances management
  - Error handling mimicking fiber node behavior
- Implemented FiberClient that allows easy switching between live and mock mode.
- Successfuly completed the end-to-end smoke testing

### What I Learned

- Channels must be connected using connect_peer before they can be opened
- Fiber uses shutdown_channel instead of close_channel.
- Amount values are represented as plain integers rather than hexadecimal.
- Fiber uses TLC (Time-Locked Contract) terminology instead of HTLC.
- Accurate error handling and state management are essential when building a reliable SDK that mirrors real node behavior
