# Day 59-65: July 9th - July 15th, 2026

## Hackathon Phase 2: Examples, Testing and Shipping

### The Goal
With the core SDK done in the first phase, I moved my focus for the week to:
- Making the SDK accessible and easier for other developers to use. 
- Create an interactive demo judges can click without installing anything.
- Write out documentations that makes the SDK feel commplete
- Run final tests and submit

### What I Did 
- I created two practical demo's inside the project, The basic-channel which demonstrates the complete lifecycle o a payement in fewer than #30 lines of code and the mock-mode example which provides a more detailed demonstration by simulating two peers exchanging payments, processing multiple micropayments, handling errors and closing channels cleanly.
- Built an interactive browser-based demo that runs entirely on the client slide just to improve usability further
- I did some documentatations by adding JSDoc comments to all classes
- Finallty debugged files, setup repo and ran final tests before submission

### What I learned 
- learned that making examples and high-quality  documentation seriously improves how developers understand and use tools.
- I also gained deeper experience designing APIs that maintain consistent behavior across different execution environments.
- Finally I learned the importance of thinking from the perspective of the end users and contributors. Rather than just building big products, I considered challenging problems developer who use JavaScript over Rust will encounter that can hinder that development and created a solution. 


### What I would do differently
I would try the node testing sooner. I have thoroughly read the documentation of the RPC and LiveClient is implemented according to the official spec, so I feel certain about the code, but testing it against a real Fiber testnet node would be a good thing to do as a final step. Running the Fiber node proved to be trickier than I expected to do within two weeks.
